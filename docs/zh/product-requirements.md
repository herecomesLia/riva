# 功能需求

## 功能总览

Riva 是面向求职者的 AI 面试训练助理。产品基于用户简历、目标岗位和练习表现，提供岗位理解、简历匹配、个性化题卡、专项练习、模拟面试、评分复盘和训练推荐等能力，帮助用户更有针对性地准备面试，并持续提升表达质量和应答表现。

围绕用户从建立求职资料、理解目标岗位，到开展训练和复盘改进的使用场景，Riva 的功能可概括为以下五类：

- **求职档案管理**：维护简历、教育经历、工作经历、项目经历、技能标签、目标岗位和求职方向，为个性化分析与训练提供基础数据。
- **岗位理解与匹配**：解析目标岗位 JD，提取岗位职责、能力要求、业务背景和高频关键词，并结合用户简历生成匹配分析报告。
- **题卡生成与单题训练**：以题卡作为最小训练单元，支持个性化题卡生成、单题训练、动态追问、评分和单题复盘。
- **专项练习与模拟面试**：提供专项练习和模拟面试两种训练方式，分别服务于单题快速改进和多题连续演练。
- **训练记录与推荐**：记录用户回答、追问、评分、复盘、薄弱项和推荐结果，用于后续题卡生成、训练建议和复盘改进。

## 语言一致性 / Interaction Language

RIVA 的核心语言规则是：用户选择什么语言，本次交互或训练产生的所有用户可见 AI 内容
就使用什么语言。当前支持 `zh-CN` 和 `en`，默认 `zh-CN`。该规则覆盖简历解析、JD
解析、匹配分析、题目和题卡、答题提示、示例回答、动态追问、评分、单题复盘、薄弱项
说明、下一题推荐、专项练习、模拟面试、用户反问反馈和整场复盘，也覆盖训练记录中由
RIVA 生成的所有人类可读内容。

### 三种语言语义

1. **UI language** 是当前界面语言，可以随时切换；真实 API 请求默认携带当前规范化的
   `Accept-Language`。
2. **Artifact language** 是一次独立 AI 结果的冻结语言。Resume Parsing、JD Parsing、
   Matching Analysis 以及未来独立生成的 QuestionCard，在调用 Agent 时捕获当前 UI
   language，并通过 `interactionLanguage` 随业务结果保存。
3. **Session language** 是连续训练的业务属性。创建 `PracticeSession` 或
   `InterviewSession` 时捕获并持久化当前 UI language；本场的 QuestionCard、Question
   Generation、Follow-up、Evaluation、Review 和 Recommendation 全部继承该值。

UI language 改变只影响导航、按钮和其他固定 UI 文案，不改变已经创建的 artifact，也不
改变活动 Session 的题目、追问、反馈或复盘。用户下一次创建新的训练 Session 时才使用
新的 UI language。历史 AI artifact、训练记录和面试记录不自动翻译；如需另一种语言，
必须通过明确的 regenerate lifecycle 实现。

### 输出语言与事实边界

自然语言描述应使用 interaction language。公司名、学校名、项目名、产品名、技能名、
编程语言、框架、数据库、协议、标准和 URL 等专有实体尽量保留原文。例如中文交互可以
输出“负责使用 Python 和 FastAPI 开发后端 API”，而不是强制翻译技术名词。语言转换不得
增加、删除或改变事实。用户的原始简历、原始 JD 和用户回答原样保存，不由 RIVA 自动翻译。

任何新的用户可见 AI workflow 都必须明确声明语言来源：独立 artifact 使用调用 Agent 时
捕获的 `interactionLanguage`，Session 子操作使用所属 Session 的 `language`。禁止使用
“检测主要语言并选择输出语言”作为新 Prompt 的主策略；只有历史兼容数据缺少语言时才
允许使用默认值 `zh-CN`。

### 当前 Agent 与未来能力

当前 Resume Parsing、JD Parsing 和 Matching Analysis 的一次性任务都把规范化语言直接传给
当前 Agent。Agent 使用自身 Prompt，且不读取 `Accept-Language`、全局 locale 或浏览器状态。
未来 QuestionCard、动态追问、评分、复盘和推荐等 Session 子 Agent 不能独立读取 UI language，必须继承 Session language；
`PracticeSession.language` 和 `InterviewSession.language` 必须在生命周期内不可变并持久化，
以保证一整轮训练不会出现中英文混杂。

## 求职档案管理

### 简历信息管理

简历信息管理用于维护用户的个人求职基础信息。Riva 后续的岗位匹配分析、题卡生成、专项练习、模拟面试、评分复盘和训练推荐，均应基于该模块中的用户信息进行个性化处理。

用户首次使用 Riva 时，需要录入简历信息。录入流程如下：

```text
用户上传或粘贴简历
→ Riva 识别简历内容
→ Riva 生成结构化信息
→ 用户确认、修改或补充
→ 保存为用户简历信息
```

当识别结果不完整或不准确时，用户可以通过表单手动补充或修正信息。

简历信息管理至少应维护以下内容：

1. 用户基本信息。
2. 教育经历。
3. 工作经历。
4. 项目经历。
5. 技能标签。
6. 证书或奖项。
7. 目标岗位。
8. 求职方向。

### 目标岗位管理

目标岗位管理用于记录用户当前准备的岗位方向，并作为 JD 解析、匹配分析、题卡生成和训练推荐的上下文。

目标岗位信息至少应包括：

1. 岗位名称。
2. 公司名称。
3. 岗位类型。
4. 岗位 JD。
5. 用户对该岗位的准备状态。

## 岗位理解与匹配

### JD 解析

Riva 应理解目标岗位 JD，并识别以下信息：

1. 岗位名称。
2. 公司名称。
3. 岗位类型。
4. 工作职责。
5. 必备技能。
6. 加分技能。
7. 经验要求。
8. 软能力要求。
9. 业务领域。
10. 高频关键词。

### 简历匹配分析

Riva 应结合用户简历和目标岗位 JD，生成匹配分析报告。报告内容包括：

1. 岗位核心要求总结。
2. 用户与岗位的匹配度分析，包括高匹配能力、缺失能力和表达不足的能力。
3. 简历亮点，例如可重点准备的项目或经历。
4. 简历不足，例如项目描述不清晰、容易被追问的薄弱点。
5. 面试准备建议。

匹配分析结果应作为后续题卡生成、专项练习推荐和模拟面试题组生成的重要依据。

## 题卡生成与单题训练

### 题卡

题卡是 Riva 中最小的面试训练单元，也是围绕一道面试题组织的结构化训练对象。专项练习和模拟面试均基于题卡展开：专项练习侧重单题即时反馈，模拟面试侧重多题连续训练和整场复盘。

题卡至少应包含以下内容：

1. 题目。
2. `language: InteractionLanguage`，明确题卡中所有 RIVA 生成的人类可读内容的语言。
3. 题目类型。
4. 难度。
5. 考察能力。
6. 推荐使用的项目或经历素材。
7. 答题提示。
8. 可能追问方向。
9. 评分参考。

题卡不能依赖文本内容猜测语言。独立题卡使用调用 Agent 时捕获的
`interactionLanguage`；属于 `PracticeSession` 或 `InterviewSession` 的题卡必须与所属
Session 的 `language` 相同。

Riva 生成个性化题卡时，应参考以下信息：

1. 用户简历信息。
2. 项目经历。
3. 技能标签。
4. 目标岗位 JD。
5. 岗位匹配分析结果。
6. 历史练习表现。
7. 当前薄弱项。

题目类型包括但不限于：

1. 项目深挖：围绕简历中的项目进行追问，可针对项目薄弱点进一步展开。
2. 行为面试：考察沟通、协作、抗压、冲突处理等能力。
3. 业务理解：考察 JD 中要求的核心能力，以及用户对目标岗位的理解。
4. 求职动机：考察用户对目标岗位的意愿、职业规划和求职逻辑。
5. 技术基础：技术类岗位专属，围绕目标岗位 JD 和用户项目技术栈中的相关技术展开。

题卡难度包括：

1. 基础：问题较直接，主要考察用户是否能清楚表达经历、能力和结果。
2. 高压：问题更开放，包含更强的追问和压力场景。

用户端题卡主要展示题目、题目类型、难度、考察能力、可选答题提示和可选推荐素材，不应默认展示完整参考答案、完整评分标准或内部追问策略。

### 单题训练

单题训练用于支持用户围绕一张题卡完成一次完整训练。单题训练应包含以下步骤：

1. 展示题目。
2. 接收用户回答。
3. 提供可选答题提示。
4. 根据用户回答进行动态追问。
5. 记录用户追问回答。
6. 对回答进行评分。
7. 生成单题复盘。
8. 识别或更新薄弱项。
9. 推荐下一题或重练当前题。

Riva 应支持对单题回答进行多维度评分。评分维度包括：

1. 内容相关性。
2. 结构清晰度。
3. 具体性。
4. 个人贡献表达。
5. 结果与数据支撑。
6. 岗位匹配度。
7. 沟通表达。
8. 风险控制。

评分结果应帮助用户理解当前回答表现，而不是仅展示分数。

单题复盘应包括：

1. 本题表现总结。
2. 回答亮点。
3. 主要问题。
4. 改进建议。
5. 可复用答题结构。
6. 是否建议重练当前题。
7. 后续训练建议。

复盘建议应具体、可执行，并与用户当前回答相关。

## 专项练习与模拟面试

### 专项练习

专项练习用于针对某一类面试题进行集中训练，核心定位是：**单题训练、即时反馈、快速改进，侧重教练式辅导**。

用户开始专项练习前，可以选择：

1. 目标岗位。
2. 题目类型。
3. 难度。
4. 是否优先练习薄弱项。
5. 是否练习收藏题目。
6. 是否重练历史题目。

专项练习按单题进行，基本流程如下：

```text
用户选择练习设置
→ Riva 呈现题目
→ 用户回答
→ Riva 根据回答进行追问或结束当前题
→ Riva 展示单题评分
→ Riva 展示单题复盘
→ Riva 推荐下一题或建议重练当前题
```

专项练习应支持以下训练行为：

1. 按题目类型练习。
2. 按目标岗位练习。
3. 按难度练习。
4. 按薄弱项练习。
5. 练习收藏题目。
6. 重练历史题目。
7. 跳过当前题。
8. 请求答题提示。
9. 请求答题框架。
10. 收藏题目。
11. 标记薄弱题。
12. 重练当前题。
13. 继续下一题。
14. 结束本轮练习。

专项练习中，每完成一道题，Riva 应立即展示单题评分、回答亮点、主要问题、改进建议、可复用答题结构、是否建议重练和下一题推荐。

专项练习中的推荐内容应结合当前题型、难度、薄弱项、历史表现和本题复盘，推荐下一题或建议重练当前题。

### 模拟面试

模拟面试用于模拟真实面试流程，核心定位是：**多题连续、流程完整、整场复盘，侧重真实面试官体验**。

用户开始模拟面试前，需要选择：

1. 目标岗位。
2. 面试轮次。
3. 难度。

面试轮次包括：

1. HR 面。
2. 业务一面。
3. 技术面。
4. 主管面。
5. 终面。
6. 综合模拟。

不同轮次的提问重点应有所不同。

模拟面试应围绕目标岗位和面试轮次生成一组面试题。一场模拟面试包含多道题，题目可以覆盖：

1. 自我介绍。
2. 项目经历深挖。
3. 岗位能力提问。
4. 行为面试提问。
5. 技术或业务理解。
6. 简历风险点追问。
7. 求职动机。
8. 用户反问环节。

不同面试轮次中，各类题目的比例应有所差异。

模拟面试按多题连续进行，基本流程如下：

```text
用户选择面试设置
→ Riva 生成面试题组
→ Riva 开场说明
→ Riva 依次提问
→ 用户逐题回答
→ Riva 根据回答动态追问
→ Riva 记录每题表现
→ Riva 进入下一题
→ 用户反问环节
→ 面试结束
→ Riva 生成整场复盘
→ Riva 更新薄弱项
→ Riva 推荐下一轮训练
```

模拟面试中，Riva 应保持面试官角色，不应在每题结束后展示详细评分和完整复盘，以免破坏连续面试体验。

模拟面试应支持以下功能：

1. 按目标岗位进行模拟。
2. 按面试轮次进行模拟。
3. 按难度进行模拟。
4. 生成一组连续面试题。
5. 进行开场说明。
6. 依次提出面试问题。
7. 根据用户回答进行动态追问。
8. 记录每题表现。
9. 支持用户反问环节。
10. 生成整场复盘报告。
11. 更新薄弱项。
12. 推荐下一轮训练方向。
13. 保存完整模拟面试记录。

模拟面试应包含用户反问环节。Riva 可以提示用户向面试官提问，并对用户反问质量进行简要反馈，给出更合适的反问建议。

用户反问可以围绕：

1. 岗位职责。
2. 团队情况。
3. 业务目标。
4. 成长路径。
5. 工作方式。
6. 面试后续流程。

模拟面试结束后，Riva 应生成整场复盘报告。整场复盘内容包括：

1. 整体表现总结。
2. 各题表现概览。
3. 主要优势。
4. 高频问题。
5. 暴露出的薄弱项。
6. 面试风险点。
7. 表达改进建议。
8. 面试前准备建议。
9. 推荐下一轮训练类型。

## 训练记录与推荐

### 练习记录管理

练习记录管理用于维护用户在 Riva 中产生的训练数据，支持后续题卡推荐、薄弱项跟踪、复盘建议和训练方向推荐。

练习记录管理至少应维护以下内容：

1. 历史专项练习记录。
2. 历史模拟面试记录。
3. 用户回答记录。
4. Riva 追问记录。
5. 用户追问回答记录。
6. 评分结果。
7. 复盘建议。
8. 薄弱项。
9. 收藏题目。
10. 标记为薄弱的题目。
11. 下一题推荐记录。
12. 下一轮训练推荐记录。

练习记录仅用于 Riva 内部的面试训练、复盘和推荐。

### 单题训练记录

Riva 应保存单题训练记录。单题记录包括：

1. 题卡信息。
2. 用户回答。
3. Riva 追问。
4. 用户追问回答。
5. 单题评分。
6. 单题复盘。
7. 暴露出的薄弱项。
8. 后续训练推荐。

### 专项练习记录

每次专项练习应保存：

1. 练习时间。
2. 目标岗位。
3. 题目类型。
4. 难度。
5. 题卡信息。
6. 用户回答。
7. Riva 追问。
8. 用户追问回答。
9. 单题评分。
10. 单题复盘。
11. 改进建议。
12. 下一题推荐。
13. 是否重练。
14. 是否收藏。
15. 是否标记为薄弱题。

### 模拟面试记录

每次模拟面试应保存：

1. 面试时间。
2. 目标岗位。
3. 面试轮次。
4. 面试难度。
5. 面试题组。
6. 用户每题回答。
7. Riva 每次追问。
8. 用户追问回答。
9. 每题表现记录。
10. 整场复盘报告。
11. 暴露出的薄弱项。
12. 下一轮训练建议。

### 薄弱项与训练推荐

Riva 应根据用户在单题训练、专项练习和模拟面试中的表现，持续识别和更新薄弱项，并据此推荐后续训练方向。

统一训练推荐结果包括：

1. 推荐下一题。
2. 推荐重练当前题。
3. 推荐调整难度。
4. 推荐切换题型。
5. 推荐继续当前题型。
6. 推荐进入模拟面试。
7. 推荐专项练习方向。
8. 推荐再次模拟面试。
9. 推荐重点复习题型。
10. 推荐原因。

训练推荐应帮助用户明确下一步是继续补强单项能力，还是进入完整面试演练。
